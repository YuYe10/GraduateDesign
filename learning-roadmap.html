PHASE
01

开发基础：编程、网络与 Linux

目标：建立安全数据分析必需的工程底座 —— 能熟练用 Python 处理数据、看懂 HTTP 报文、在 Linux 上部署服务。此阶段不追求深度，追求"够用且顺手"。

建议周期 · 4 ~ 6 周
0 / 0

1.1Python 编程（主力语言）

安全数据处理、建模、写工具脚本都离不开 Python，要求达到能独立写 200 行数据处理脚本的熟练度。

Python 语法与标准库：数据结构、文件 I/O、正则、json、多线程基础
边学边练：用 Python 写一个"统计文本中 IP 出现次数并输出 Top10"的小脚本作为结业练习。

虚拟环境与包管理：venv / conda、pip、requirements.txt
毕设期间至少会维护 2~3 个项目环境（数据处理、模型训练、Web 服务），环境隔离从第一天做起。
DOCvenv 官方文档 DOCConda 快速上手
Git 版本控制：commit / branch / merge / rebase / 远程协作
毕设代码必须进 Git 仓库，既是备份也是答辩时"工作量与迭代过程"的证据。

1.2计算机网络与 HTTP

入侵检测、流量分析的原料就是网络数据。至少要能读懂一次 HTTP 请求的完整生命周期、TCP 三次握手、常见端口与协议字段。

TCP/IP 与 HTTP 协议核心：报文结构、状态码、Header、TLS 握手
建议配合 Wireshark 抓包对照学习，看到真实报文后概念会立刻落地。
DOCMDN · HTTP 完全指南 VIDEO湖科大教书匠《计算机网络微课堂》（B 站） DOCRFC 9110 · HTTP Semantics（进阶查阅）
抓包实操：用 Wireshark 分析一次完整 HTTP / DNS 会话
能回答：三次握手在哪几帧、DNS 查询问了什么、响应 Content-Type 是什么。这是流量分析的第一次"手感"。
DOCWireshark 官方用户指南 DATAWireshark 官方示例抓包集

1.3Linux 与命令行

Linux 基础：文件系统、权限、进程管理、ssh、常见日志位置
重点关注 /var/log 下的日志体系（auth.log、syslog、nginx access log）—— 它们就是日后日志异常检测的数据源。
BOOK鸟哥的 Linux 私房菜（基础篇） COURSELinux Journey（免费交互课程）
Shell 与文本处理三剑客：grep / awk / sed
结业练习：用一条命令从 nginx access.log 中统计"状态码为 404 且访问 .php 路径的 IP 频次 Top10"——这就是最原始的日志异常分析。
DOCLinux 命令大全（中文速查） VIDEOShell 文本处理实战（B 站）

目标：能独立做出毕设的"系统外壳" —— 一个带登录、数据展示大屏、RESTful API 的完整 Web 应用。安全方向的毕设，系统完成度是拉开档次的关键。

03

安全基础：Web 安全与攻防入门

目标：理解"攻击长什么样"，才能谈"检测攻击"。掌握 OWASP Top 10 漏洞原理，在靶场里亲手打一遍，再看日志里留下的痕迹 —— 这是安全数据分析的直觉来源。

建议周期 · 5 ~ 8 周（可与阶段四并行）

3.1Web 漏洞原理

OWASP Top 10：注入、XSS、SSRF、文件上传、反序列化、访问控制失效…
每个漏洞要求能讲清：成因 → 攻击 payload → 日志/流量特征 → 检测思路。最后一条正是异常检测的特征工程素材。

Burp Suite 抓包改包：Repeater / Intruder / 插件生态
安全人员的"主力 IDE"。重点理解每一个攻击请求在 HTTP 层面的形态 —— 之后做 WAF/IDS 特征时你就在和这些形态打交道。
DOCBurp Suite 官方文档 VIDEOBurp Suite 使用教程（B 站）

LABWeb Security Academy（强烈推荐） LABDVWA 本地靶场（PHP） LABWebGoat（Java 教学靶场）
CTF 入门：Web / Misc 方向，攻防世界新手区 + picoCTF

机器学习与异常检测（核心阶段）

目标：建立"基线 → 对比 → 改进"的实验方法论，掌握异常检测主流算法族，并能在公开安全数据集上完整跑通一次评估。这是毕设论文的核心章节来源。

5.1机器学习通识

机器学习基础：监督/无监督、过拟合、交叉验证、评估指标体系
安全场景极度类别不平衡，必须吃透 Precision / Recall / F1 / ROC-AUC / PR-AUC 的区别 —— 只报 Accuracy 的毕设会被评委当场拆穿。

5.2异常检测算法族（毕设主力）

统计与距离类：3σ / 箱线图规则、KNN 距离、LOF 局部离群因子
先理解"异常 = 偏离正常分布"的统一视角；这些方法是必做的 baseline。

树模型类：Isolation Forest、One-Class SVM、XGBoost（有标签时）
Isolation Forest 是安全日志检测的"国民算法"，务必搞懂原理并亲手调参（n_estimators、contamination）。

重构与序列类：Autoencoder、LSTM 时序异常检测
AE 用重构误差做异常分数，LSTM 用预测误差 —— 这两个是论文创新点的常见载体（改进网络结构、注意力、对比学习…）。
DOCPyTorch Autoencoder 教程 COURSELSTM-AE 时序异常检测完整实战（英文）

产出物：一个 Notebook + 一张指标对比表 + 一张 ROC 曲线图。这就是毕设论文实验章节的雏形。

PHASE
08

GRADUATION DESIGN PROPOSALS

四个可直接落地的毕设选题建议

难度由低到高排列。前两个偏"系统 + 应用"，工作量稳、演示效果好；后两个偏"研究 + 创新"，论文上限高。所有选题都默认含一个可演示的 Web 系统 —— 这正是前面阶段二、三、五、六的合流之处。

选题一 · 基于机器学习的网络入侵检测系统（NIDS）

★★★
推荐 · 稳妥均衡
数据集CIC-IDS2017（主）/ NSL-KDD（对比复现）
技术栈Pandas + scikit-learn / PyTorch · FastAPI · Vue3 + ECharts 大屏
核心内容
  • 流量特征工程复现（CICFlowMeter 80 维特征）
  • 基线模型（RF / XGBoost）与深度模型（MLP / LSTM）对比实验
  • 类别不平衡处理（SMOTE / 类别权重）消融实验
  • 在线检测服务：上传流量 CSV → 返回告警与置信度
  • 态势感知大屏：攻击类型分布、来源 IP TopN、时序曲线
可选创新点：不平衡学习改进、SHAP 告警可解释面板、特征选择降维后的轻量化部署对比。
风险提示：数据集大（全量约 50GB pcap），建议先用官方 CSV 特征子集；对比实验要控制变量，别堆模型数量。

选题二 · 基于日志的异常行为检测与攻击溯源分析平台

★★★☆
数据集Loghub HDFS / Linux auth.log（自建靶场产生）/ nginx access log
技术栈ELK（采集）· Drain 日志模板解析 · Isolation Forest / 序列模型 · FastAPI + Vue3
核心内容
  • 自建 DVWA 靶场并真实攻击，采集一手攻击日志
  • 日志模板解析（Drain）把非结构化日志事件化
  • 无监督异常检测（IF / LOF / DeepLog 思路二选一）
  • 告警 → ATT&CK 技术映射，生成"攻击链时间线"视图
  • 规则引擎 + ML 双通道检测的互补性分析
可选创新点："自己攻击自己检测"的数据闭环是天然的故事线；ATT&CK 覆盖度分析可作单独一章。
风险提示：日志解析细节繁琐，预留充足时间；DeepLog 复现成本高于预期，先保 Isolation Forest 基线。

选题三 · 面向入侵检测模型的对抗样本攻防博弈实验平台

★★★★
研究型 · 论文上限高
数据集CIC-IDS2017 特征 CSV（表格特征即可）
技术栈PyTorch · IBM ART · 博弈论建模 · 可视化平台（可选简化版）
核心内容
  • 训练流量二分类器（MLP）作为"受害者模型"
  • 实现带可行性约束的对抗扰动（只改可被攻击者操纵的特征）
  • 评估攻击成功率与扰动代价的权衡曲线
  • 对抗训练 / 特征压缩 / 集成检测三种防御对比
  • 用 Stackelberg 博弈框架讨论攻防收益矩阵
可选创新点："约束条件设计"和"攻防闭环评估"本身就是贡献点；可发表/投递小论文。
风险提示：需要扎实的 PyTorch 与论文阅读能力；Web 平台可做精简版，把精力留给实验。

选题四 · 基于深度学习的恶意域名（DGA）检测与家族分类

★★★
数据集Alexa/Tranco 白名单 + 360 Netlab DGA 家族样本
技术栈字符级 CNN / LSTM / 小型 Transformer · FastAPI · 大屏展示
核心内容
  • 字符级建模：域名 → 序列 → 二分类（DGA / 正常）
  • 多分类：DGA 家族识别与小样本家族问题
  • CNN / LSTM / Transformer 三架构公平对比
  • 在线检测 API + 域名家族画像页面
  • 对抗视角：人工构造"拟人化"域名评估绕过率
可选创新点：训练快、数据轻，适合把"对抗绕过 + 防御"做成一章，兼顾选题三的思想但成本更低。
风险提示：故事完整度依赖对比与消融实验的设计，避免只报一个准确率就收尾。

PRACTICAL ADVICE

给安全方向毕设的五条实战建议

系统完成度 > 模型新高度

评委 80% 的印象来自可运行的演示。一个能现场上传数据、实时出告警、有大屏的系统，胜过纸面上高 0.5% 的 F1。先保底线，再冲上限。

实验设计先行

开题后就固定：数据集版本、划分方式、指标、对比方法。中途改评估协议是大忌 —— 之前所有实验数字都会作废。

自建靶场 = 一手数据

DVWA + Burp 打一轮并采集日志，你就拥有了"真实攻击 + 真实标注"的数据闭环。论文里写"自建实验环境采集数据"，可信度和故事性立刻不同。

警惕只报 Accuracy

攻击样本占 1% 的数据集上，"全部判正常"也有 99% 准确率。报告 Precision / Recall / F1 / PR-AUC，并在不平衡设置下讨论 —— 这是评委最爱挖的坑。

每周留档，答辩不慌

每周往仓库提交一次（代码、图表、实验记录）。它们最终会变成：论文图表、答辩素材、工作证明 —— 以及被问"这个结果是哪来的"时的底气。
